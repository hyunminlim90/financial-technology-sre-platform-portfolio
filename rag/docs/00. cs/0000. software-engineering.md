# Software Engineering (소프트웨어 공학)

> 정독: 1회

## 1. 무엇인가

소프트웨어 공학(Software Engineering)은 「소프트웨어」를 「체계적이고 예측 가능하게」 「개발, 운영, 유지보수」 하기 위한 「공학적 접근 방법」 이다.

단순히 「프로그램을 작성하는 기술」 이 아니라 다음을 포함한다.

- 요구사항 정의
- 설계
- 구현
- 테스트
- 배포
- 운영
- 유지보수
- 프로세스 관리

> 목표는 제한된 시간과 비용 안에서 품질이 검증된 소프트웨어를 지속적으로 제공하는 것이다.

## 2. 시스템 어디에서 등장하는가

소프트웨어 공학은 특정 계층에만 존재하지 않는다.

전체 소프트웨어 생명주기(SDLC)에 적용된다.

| 단계 |
|------|
| 기획 |
| 요구사항 분석 |
| 아키텍처 설계 |
| 개발 |
| 테스트 |
| 배포 |
| 운영 |
| 유지보수 |

즉, 다음 모든 소프트웨어 시스템에서 공통적으로 사용된다.

- Frontend
- Backend
- Database
- Cloud
- Embedded
- Mobile
- AI
- Infrastructure

---

## 3. 어떤 자원에 가장 영향이 큰가

소프트웨어 공학은 특정 하드웨어 자원보다 **개발 조직의 자원**에 직접적인 영향을 준다.

**직접 영향:**
- 개발 시간
- 개발 비용
- 운영 비용
- 인력 비용
- 품질 관리 비용

**간접 영향** — 설계 품질에 따라 다음 사용 효율도 달라질 수 있다.
- CPU
- Memory
- Network
- Disk

---

## 4. 왜 중요한가

소프트웨어는 시간이 지날수록 규모가 커지고 복잡해진다.

공학적 관리가 없으면 다음 문제가 발생한다.

- 일정 지연
- 예산 초과
- 품질 저하
- 장애 증가
- 유지보수 어려움
- 기술 부채 증가

> 소프트웨어 공학은 이러한 문제를 줄이고 장기간 운영 가능한 시스템을 만들기 위해 필요하다.

---

## 5. 실제 장애와 어떤 관련이 있는가

많은 운영 장애는 기술 자체보다 **설계와 개발 과정의 문제**에서 시작된다.

**대표 원인:**
- 요구사항 누락
- 설계 오류
- 테스트 부족
- 배포 프로세스 부재
- 운영 절차 미정의

**예시:**

| 원인 | 결과 |
|------|------|
| 트랜잭션 설계 오류 | 데이터 정합성 문제 |
| 테스트 부족 | 운영 장애 발생 |
| 배포 전략 부재 | 대규모 서비스 중단 |
| 모니터링 설계 누락 | 장애 탐지 실패 |

> 따라서 장애 대응뿐 아니라 **장애 예방**에도 소프트웨어 공학이 중요하다.

## 6. 현재 문맥에서 꼭 알아야 하는 핵심 메커니즘

E2E SRE 문서를 읽는 관점에서 가장 중요한 개념은 다음 네 가지이다.

| 개념 | 핵심 질문 |
|------|-----------|
| 요구사항 관리 | 무엇을 만들어야 하는가 |
| 설계 | 어떻게 만들 것인가 |
| 검증 | 정상 동작을 어떻게 확인할 것인가 |
| 유지보수 | 변경과 장애를 어떻게 관리할 것인가 |

대부분의 SRE 활동은 **운영 · 품질 · 가용성 · 변경 관리**를 다루므로 소프트웨어 공학의 연장선에 있다.

---

## 7. Linux / Runtime / Kubernetes 에서 어디서 관측되는가

소프트웨어 공학 자체는 운영체제나 런타임의 기능이 아니다.  
따라서 Linux 커널이나 JVM 내부에서 직접 관측되지는 않는다.  
대신 **결과물**로 관측된다.

**Linux**
- 서비스 프로세스
- 로그
- 모니터링 지표
- 배포 결과

**Runtime**
- 예외 처리 구조
- 메모리 사용 패턴
- 스레드 모델
- GC 동작

**Kubernetes**
- Deployment
- Service
- ConfigMap
- CI/CD Pipeline
- GitOps 구조
- 운영 정책

**전체 흐름:**

```
Software Engineering
        ↓
Architecture
        ↓
Implementation
        ↓
Deployment
        ↓
Runtime Behavior
```

형태로 최종 시스템에서 나타난다.

## E2E SRE 문서 관점 핵심 정리

> 소프트웨어 공학은 소프트웨어를 개발하고 운영하는 전체 과정을 체계적으로 관리하기 위한 공학적 방법론이다.

관심 대상은 코드 자체가 아니라 **전 과정**이다.

- 요구사항
- 설계
- 구현
- 검증
- 배포
- 운영
- 유지보수

**SRE, DevOps, 플랫폼 엔지니어링**은 소프트웨어 공학의 운영 단계와 품질 보증 단계를 확장한 실무 분야로 볼 수 있다.
