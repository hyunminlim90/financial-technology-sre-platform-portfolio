# Computer Programming (컴퓨터 프로그래밍)

> 정독: 1회

## 1. 무엇인가

컴퓨터 프로그래밍(Computer Programming)은 「컴퓨터」 가 특정 작업을 수행할 수 있도록 알고리즘을 설계하고, 이를 프로그래밍 언어로 구현하여 실행 가능한 소프트웨어를 만드는 과정이다.

컴퓨터 프로그래밍은 단순히 소스코드를 작성하는 것만 의미하지 않으며, 문제 분석부터 구현, 테스트, 유지보수까지 포함하는 소프트웨어 개발 활동이다.

주요 목적은 다음과 같다.

- 문제 해결
- 알고리즘 구현
- 소프트웨어 개발
- 자동화
- 기능 구현
- 유지보수

컴퓨터 프로그래밍은 애플리케이션 소프트웨어를 구현하는 핵심 활동이다.

## 2. 시스템 어디에서 등장하는가

컴퓨터 프로그래밍은 애플리케이션을 구현하는 과정에서 수행된다.

전체 구조는 다음과 같다.

```
Requirement
      ↓
Design
      ↓
Programming
      ↓
Build
      ↓
Execution
```

프로그래밍은 일반적으로 다음 요소를 대상으로 수행된다.

- 알고리즘
- 데이터 구조
- 비즈니스 로직
- 입출력 처리
- 오류 처리

프로그램 실행 흐름은 일반적으로 다음과 같다.

```
Input
      ↓
Processing
      ↓
Output
```

## 3. 어떤 자원(CPU/Memory/Network/Disk)에 가장 영향이 큰가

프로그래밍은 모든 시스템 자원의 사용 방식을 결정한다.

| 자원 | 영향 |
|---|---|
| CPU | 연산 및 명령 실행 |
| Memory | 데이터 및 프로그램 실행 |
| Network | 데이터 송수신 |
| Disk | 파일 및 데이터 저장 |

### CPU

대표 작업

- 연산 수행
- 조건 분기
- 반복 처리

### Memory

대표 작업

- 데이터 저장
- 객체 생성
- 버퍼 관리

### Network

대표 작업

- 데이터 송수신
- 원격 통신
- 서비스 호출

### Disk

대표 작업

- 파일 읽기
- 파일 저장
- 로그 기록

## 4. 왜 중요한가

모든 소프트웨어의 동작은 프로그래밍을 통해 구현된다.

프로그래밍의 품질은 다음과 같은 시스템 특성에 영향을 준다.

- 정확성
- 성능
- 안정성
- 유지보수성
- 확장성
- 신뢰성

동일한 기능이라도 구현 방식에 따라 시스템의 성능과 자원 사용량은 크게 달라질 수 있다.

## 5. 실제 장애와 어떤 관련이 있는가

운영 환경에서 발생하는 많은 장애는 프로그래밍 과정에서 작성된 로직과 직접 관련된다.

### CPU 관련

**원인**

- 비효율적인 알고리즘
- 과도한 반복 연산
- 불필요한 계산

**결과**

- CPU Usage 증가
- Latency 증가
- 처리량 감소

### Memory 관련

**원인**

- 메모리 누수
- 과도한 객체 생성
- 버퍼 증가

**결과**

- Memory Usage 증가
- OOM
- 프로세스 종료

### Network 관련

**원인**

- 과도한 네트워크 요청
- 재시도 증가
- 연결 관리 오류

**결과**

- Timeout
- Connection Failure
- 응답 지연

### Disk 관련

**원인**

- 과도한 파일 접근
- 로그 증가
- 비효율적인 저장 방식

**결과**

- Disk I/O 증가
- 응답시간 증가
- 저장 실패

### 프로그램 관련

**원인**

- 논리 오류
- 예외 처리 누락
- 동시성 문제
- 입력 검증 부족

**결과**

- 프로그램 종료
- 기능 오류
- 서비스 장애

## 6. 현재 문맥에서 꼭 알아야 하는 핵심 메커니즘만 설명

E2E SRE 문서를 읽는 관점에서는 컴퓨터 프로그래밍을 다음 여섯 단계로 이해하면 충분하다.

### 문제 분석

해결해야 할 문제를 정의한다.

- Requirement Analysis

### 알고리즘 설계

문제를 해결하는 절차를 정의한다.

- Algorithm Design

### 구현

알고리즘을 프로그래밍 언어로 작성한다.

- Source Code

### 빌드

실행 가능한 프로그램을 생성한다.

- Compile
- Interpret
- Build

### 실행

프로그램을 실행하여 결과를 생성한다.

- Execution

### 유지보수

기능 개선과 오류를 수정한다.

- Bug Fix
- Refactoring
- Enhancement

### 핵심 흐름

```
Requirement
      ↓
Algorithm
      ↓
Programming
      ↓
Build
      ↓
Execution
      ↓
Maintenance
```

E2E SRE 관점에서는

> 어떤 언어를 사용하는가

보다

- 프로그램이 어떻게 구현되는가
- 어떻게 실행되는가
- 자원을 어떻게 사용하는가
- 장애 발생 시 어떻게 동작하는가

를 이해하는 것이 중요하다.

## 7. Linux / Runtime / Kubernetes에서 어디서 관측되는가

컴퓨터 프로그래밍의 결과물은 운영 환경의 여러 계층에서 관측된다.

### Linux

**관측 대상**

- Process
- CPU Usage
- Memory Usage
- Disk I/O
- Network Usage

**대표 도구**

```
top
ps
vmstat
iostat
sar
ss
```

### Runtime

**관측 대상**

- Application 상태
- Exception
- Request Rate
- Response Time
- Error Rate
- Logs

**대표 자료**

- Metrics
- Logs
- Traces

### Kubernetes

**관측 대상**

- Pod
- Container
- Restart Count
- Resource Usage
- Health Check
- Deployment 상태

**대표 명령**

```
kubectl get
kubectl describe
kubectl logs
kubectl top
```

## E2E SRE 문서 관점 핵심 정리

컴퓨터 프로그래밍은

> 문제를 해결하기 위한 알고리즘을 프로그래밍 언어로 구현하여 실행 가능한 소프트웨어를 만드는 과정이다.

핵심 과정은

- Problem Analysis
- Algorithm Design
- Programming
- Build
- Execution
- Maintenance

이다.

E2E SRE 관점에서는

```
Requirement
      ↓
Programming
      ↓
Application
      ↓
CPU / Memory / Network / Disk 사용 특성
      ↓
Observability
```

의 흐름으로 이해하면 된다.

운영 환경에서 관측되는

- CPU Usage 증가
- Memory Leak
- OOM
- Timeout
- Application Error
- Process 종료
- Disk I/O 증가

등은 대부분 프로그램의 구현 방식, 자원 사용 방식 또는 예외 처리 방식과 관련된 문제에서 발생한다.

컴퓨터 프로그래밍의 핵심은 단순히 코드를 작성하는 것이 아니라, 요구사항을 실행 가능한 소프트웨어로 구현하고 시스템 자원을 효율적으로 활용하여 안정적으로 동작하는 프로그램을 만드는 것이다.
