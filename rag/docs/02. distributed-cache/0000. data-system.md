# Data System (데이터 시스템)

> 정독: 1회

## 1. 무엇인가

데이터 시스템(Data System)은 「애플리케이션」 에서 사용하는 「데이터를 생성」, 저장, 조회, 수정, 전달, 처리, 보관 및 삭제하는 전 과정을 관리하는 시스템이다.

데이터 시스템은 단일 데이터 저장소를 의미하지 않으며, 다양한 데이터 처리 구성 요소가 함께 동작하는 구조를 의미한다.

데이터 시스템의 목적은 다음과 같다.

- 데이터 저장
- 데이터 조회
- 데이터 전달
- 데이터 처리
- 데이터 보호
- 데이터 관리

데이터 시스템은 데이터의 생명주기(Lifecycle)를 안정적으로 관리하는 기반 시스템이다.

## 2. 시스템 어디에서 등장하는가

데이터 시스템은 애플리케이션과 사용자 사이에서 데이터를 관리한다.

전체 구조는 다음과 같다.

```
User
  ↓
Application
  ↓
Data System
  ↓
Storage
```

데이터 시스템은 일반적으로 다음 기능으로 구성된다.

- 데이터 저장
- 데이터 캐싱
- 데이터 검색
- 데이터 전달
- 데이터 처리

데이터 흐름은 일반적으로 다음과 같이 이루어진다.

```
Data Creation
  ↓
Storage
  ↓
Processing
  ↓
Retrieval
  ↓
Update
  ↓
Deletion
```

## 3. 어떤 자원(CPU/Memory/Network/Disk)에 가장 영향이 큰가

데이터 시스템은 시스템의 모든 주요 자원을 사용하는 대표적인 구성 요소이다.

| 자원 | 영향 |
|---|---|
| CPU | 데이터 처리 및 질의 실행 |
| Memory | 캐시 및 버퍼 관리 |
| Network | 데이터 송수신 및 복제 |
| Disk | 데이터 저장 및 조회 |

### CPU
**대표 작업**
- 질의 처리
- 데이터 계산
- 정렬
- 집계

### Memory
**대표 작업**
- 캐시
- 버퍼
- 메타데이터 관리

### Network
**대표 작업**
- 데이터 복제
- 데이터 전송
- 노드 간 통신

### Disk
**대표 작업**
- 데이터 저장
- 데이터 조회
- 로그 기록
- 복구 데이터 저장

## 4. 왜 중요한가

대부분의 애플리케이션은 데이터를 중심으로 동작한다.

데이터 시스템은 다음 품질 특성에 직접적인 영향을 준다.

- 신뢰성
- 가용성
- 확장성
- 일관성
- 성능
- 복구성

데이터 시스템의 품질은 서비스 전체 품질과 직결된다.

---

## 5. 실제 장애와 어떤 관련이 있는가

운영 환경에서 발생하는 많은 장애는 데이터 시스템과 직접 연결된다.

### CPU 관련
**원인**
- 복잡한 질의
- 과도한 연산
- 비효율적인 데이터 처리

**결과**
- CPU Usage 증가
- Latency 증가
- 처리량 감소

### Memory 관련
**원인**
- 캐시 부족
- 메모리 부족
- 버퍼 사용 증가

**결과**
- Memory Usage 증가
- Cache Miss 증가
- 응답시간 증가

### Network 관련
**원인**
- 데이터 복제
- 대량 데이터 전송
- 노드 간 통신 증가

**결과**
- Network Saturation
- Replication Delay
- Timeout

### Disk 관련
**원인**
- 과도한 읽기
- 과도한 쓰기
- 디스크 공간 부족

**결과**
- Disk I/O 증가
- Storage Bottleneck
- 응답시간 증가

### 데이터 관련
**원인**
- 복제 실패
- 동기화 지연
- 저장 오류

**결과**
- 데이터 불일치
- 데이터 손실
- 서비스 장애

## 6. 현재 문맥에서 꼭 알아야 하는 핵심 메커니즘만 설명

E2E SRE 문서를 읽는 관점에서는 데이터 시스템을 다음 다섯 가지 기능으로 이해하면 충분하다.

### 저장(Storage)
데이터를 지속적으로 보관한다.
- Write
- Update
- Delete

### 조회(Retrieval)
필요한 데이터를 검색하여 제공한다.
- Read
- Search
- Filter

### 캐싱(Caching)
자주 사용하는 데이터를 빠르게 제공한다.
- Memory Cache
- Temporary Data

### 전달(Transport)
데이터를 시스템 간에 전달한다.
- Message
- Event
- Replication

### 처리(Processing)
데이터를 변환하고 계산한다.
- Aggregation
- Transformation
- Validation

### 핵심 흐름

```
Create
  ↓
Store
  ↓
Process
  ↓
Transfer
  ↓
Read
  ↓
Delete
```

> **E2E SRE 관점**에서는 "데이터를 어디에 저장하는가"보다 데이터가 **어떻게 저장되고, 어떻게 이동하며, 어떻게 처리되고, 어떻게 보호되는가**를 이해하는 것이 중요하다.

## 7. Linux / Runtime / Kubernetes 에서 어디서 관측되는가

데이터 시스템은 운영 환경에서 다양한 형태로 관측된다.

### Linux

**관측 대상**
- CPU Usage
- Memory Usage
- Disk Usage
- Disk I/O
- Network Usage
- Process 상태

**대표 도구**
- `top`
- `vmstat`
- `iostat`
- `sar`
- `ss`
- `df`

### Runtime

**관측 대상**
- Query Latency
- Cache Hit Ratio
- Connection 수
- Buffer 사용량
- Replication 상태
- Error Rate

**대표 자료**
- Metrics
- Logs
- Traces
- Slow Query Log

### Kubernetes

**관측 대상**
- Pod 상태
- Persistent Volume
- Persistent Volume Claim
- CPU Usage
- Memory Usage
- Restart Count

**대표 명령**
- `kubectl get`
- `kubectl describe`
- `kubectl logs`
- `kubectl top`

## E2E SRE 문서 관점 핵심 정리

데이터 시스템은 데이터를 **생성**하고, **저장**하고, **처리**하고, **전달**하고, **조회**하고, **삭제**하는 전 과정을 관리하는 시스템이다.

**핵심 기능**은 다음과 같다.
- Storage
- Retrieval
- Caching
- Transport
- Processing

**E2E SRE 관점**에서는 다음 흐름으로 이해하면 된다.

```
Application
  ↓
Data System
  ↓
CPU / Memory / Network / Disk 사용 특성
  ↓
Observability
```

운영 환경에서 관측되는 다음 현상들은 대부분 데이터 시스템의 처리 방식과 자원 사용 특성에서 비롯된다.

- CPU 사용률 증가
- Memory 부족
- Cache Miss 증가
- Disk I/O 증가
- Network 지연
- Replication Delay
- Storage Bottleneck

데이터 시스템은 서비스의 기능뿐만 아니라 **성능, 가용성, 확장성, 데이터 일관성 및 복구 능력**을 결정하는 핵심 구성 요소이다.
