# Kubernetes (쿠버네티스)

> 정독: 1회

## 1. 무엇인가

쿠버네티스(Kubernetes)는 「컨테이너」 화된 애플리케이션의 배포, 실행, 확장, 복구 및 운영을 자동으로 관리하는 컨테이너 오케스트레이션 플랫폼(Container Orchestration Platform)이다.

쿠버네티스의 목적은 여러 서버에 분산된 애플리케이션을 일관된 방식으로 운영하고, 원하는 상태를 지속적으로 유지하는 것이다.

주요 목적은 다음과 같다.

- 애플리케이션 배포
- 애플리케이션 실행
- 서비스 확장
- 장애 복구
- 자원 관리
- 운영 자동화

쿠버네티스는 단일 서버가 아닌 여러 서버를 하나의 클러스터로 관리하는 플랫폼이다.

## 2. 시스템 어디에서 등장하는가

쿠버네티스는 애플리케이션과 운영체제 사이에서 컨테이너 실행 환경을 관리한다.

전체 구조는 다음과 같다.

```
Application
      ↓
Container
      ↓
Kubernetes
      ↓
Container Runtime
      ↓
Operating System
      ↓
Hardware
```

클러스터는 일반적으로 다음과 같이 구성된다.

```
Control Plane
      ↓
Worker Node
      ↓
Container
```

쿠버네티스는 다음 요소를 관리한다.

- 컨테이너
- Pod
- Node
- Service
- Storage
- Network

## 3. 어떤 자원(CPU/Memory/Network/Disk)에 가장 영향이 큰가

쿠버네티스는 시스템의 모든 주요 자원을 관리한다.

| 자원 | 영향 |
|---|---|
| CPU | 스케줄링, 자원 할당, 자동 확장 |
| Memory | 컨테이너 메모리 관리 |
| Network | 서비스 통신, 로드 밸런싱 |
| Disk | 영구 저장소 및 볼륨 관리 |

### CPU

대표 작업

- CPU Scheduling
- Resource Allocation
- Autoscaling

### Memory

대표 작업

- Memory Limit
- Memory Request
- OOM 관리

### Network

대표 작업

- Service Routing
- Load Balancing
- Cluster Networking

### Disk

대표 작업

- Persistent Storage
- Volume Mount
- Stateful Data

## 4. 왜 중요한가

대규모 서비스에서는 수많은 컨테이너를 안정적으로 운영해야 한다.

쿠버네티스는 이를 자동화하여 다음과 같은 품질 특성을 제공한다.

- 가용성
- 확장성
- 복구성
- 자동화
- 운영 일관성

쿠버네티스는 애플리케이션의 실행 상태를 지속적으로 관리하고, 장애가 발생하면 자동으로 복구를 시도한다.

## 5. 실제 장애와 어떤 관련이 있는가

운영 환경에서는 쿠버네티스 구성 요소와 클러스터 자원 상태가 다양한 장애의 원인이 될 수 있다.

### CPU 관련

**원인**

- Node CPU 부족
- Resource Limit 설정 오류
- 과도한 Pod 실행

**결과**

- Scheduling 실패
- Latency 증가
- 처리량 감소

### Memory 관련

**원인**

- Memory 부족
- Memory Limit 초과
- Node Memory 부족

**결과**

- OOMKill
- Pod Restart
- 서비스 불안정

### Network 관련

**원인**

- 네트워크 지연
- Service 연결 실패
- DNS 오류

**결과**

- Timeout
- Connection Failure
- Packet Loss

### Disk 관련

**원인**

- Volume 부족
- Storage 장애
- Disk I/O 증가

**결과**

- Persistent Volume 장애
- 데이터 저장 실패
- 응답시간 증가

### 클러스터 관련

**원인**

- Node 장애
- Control Plane 장애
- Container Runtime 장애

**결과**

- Pod 생성 실패
- 서비스 중단
- 복구 지연

## 6. 현재 문맥에서 꼭 알아야 하는 핵심 메커니즘만 설명

E2E SRE 문서를 읽는 관점에서는 쿠버네티스를 다음 여섯 가지 기능으로 이해하면 충분하다.

### 스케줄링(Scheduling)

컨테이너를 실행할 노드를 결정한다.

```
Pod
      ↓
Node 선택
```

### 상태 유지(Reconciliation)

현재 상태를 원하는 상태와 지속적으로 비교한다.

```
Current State
      ↓
Desired State
      ↓
Synchronization
```

### 서비스 연결(Service Networking)

애플리케이션 간 통신을 관리한다.

```
Client
      ↓
Service
      ↓
Pod
```

### 자원 관리(Resource Management)

CPU와 메모리를 관리한다.

- Request
- Limit
- Allocation

### 자동 복구(Self-healing)

장애가 발생한 구성 요소를 복구한다.

```
Failure
      ↓
Detection
      ↓
Recovery
```

### 자동 확장(Scaling)

부하에 따라 실행 개수를 조정한다.

```
Load 증가
      ↓
Scale Out

Load 감소
      ↓
Scale In
```

### 핵심 흐름

```
Deployment
      ↓
Scheduling
      ↓
Execution
      ↓
Monitoring
      ↓
Recovery
```

E2E SRE 관점에서는

> 컨테이너를 어떻게 실행하는가

보다

- 애플리케이션이 어디에서 실행되는가
- 얼마나 안정적으로 유지되는가
- 장애 발생 시 어떻게 복구되는가
- 부하 변화에 어떻게 대응하는가

를 이해하는 것이 중요하다.

## E2E SRE 문서 관점 핵심 정리

쿠버네티스는

> 컨테이너화된 애플리케이션을 배포하고, 실행하고, 확장하고, 복구하는 컨테이너 오케스트레이션 플랫폼이다.

핵심 기능은

- Scheduling
- Resource Management
- Service Networking
- Self-healing
- Scaling
- State Reconciliation

이다.

E2E SRE 관점에서는

```
Application
      ↓
Container
      ↓
Kubernetes
      ↓
CPU / Memory / Network / Disk 사용 특성
      ↓
Observability
```

의 흐름으로 이해하면 된다.

운영 환경에서 관측되는

- Pod Restart
- OOMKill
- Scheduling Failure
- Node NotReady
- Network Timeout
- Persistent Volume 장애
- CrashLoopBackOff
- Image Pull 실패

등은 대부분 쿠버네티스의 자원 관리, 스케줄링 또는 클러스터 상태와 관련된 문제에서 발생한다.

쿠버네티스의 핵심은 단순히 컨테이너를 실행하는 것이 아니라, 클러스터의 현재 상태를 지속적으로 관찰하고 원하는 상태를 유지하도록 자동으로 조정하는 것이다.
