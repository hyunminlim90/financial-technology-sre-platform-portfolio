# 부호 없는 타입 속성 (Unsigned Type Attribute)

> 정독: 0회

## 1. 이 기술이 무엇인가

부호 없는 타입 속성(Unsigned Type Attribute)은:

> 정수 데이터를 음수 없이 0과 양수만 표현하도록 지정하는 타입 속성

대표적인 예:

- `unsigned char`
- `unsigned short`
- `unsigned int`
- `unsigned long`

핵심은 다음입니다.

**모든 비트를 숫자의 크기(Magnitude) 표현에 사용한다.**

`signed`처럼 부호를 표현하기 위한 별도 규칙을 적용하지 않습니다.

---

## 2. 시스템 어디에서 등장하는가

**CPU 정수 연산**
- 카운터, 인덱스, 길이, 크기, 오프셋

**메모리 주소 처리**
- 주소, 주소 오프셋, 메모리 크기

**비트 필드**
- 상태 플래그, 제어 플래그, 하드웨어 레지스터

**네트워크 프로토콜**
- 패킷 길이, 포트 번호, 플래그 비트, 시퀀스 번호

**파일 시스템**
- 파일 크기, 블록 번호, inode 번호

---

## 3. 어떤 자원(CPU/Memory/Network/Disk)에 가장 영향이 큰가

가장 직접적인 영향은 **CPU**입니다. CPU가 해당 데이터를 음수 없는 정수로 해석하기 때문입니다.

그 다음은 **Memory, Network, Disk**입니다. 크기나 길이를 표현하는 필드 대부분이 `unsigned`이기 때문입니다.

- 패킷 길이
- 파일 크기
- 메모리 크기

---

## 4. 왜 중요한가

같은 비트 수에서 더 넓은 양수 범위를 사용할 수 있습니다.

N비트 unsigned 범위: `0` ~ `2^N - 1`

| 비트 수 | signed | unsigned |
|---|---|---|
| 8bit | -128 ~ 127 | 0 ~ 255 |
| 16bit | -32768 ~ 32767 | 0 ~ 65535 |
| 32bit | 약 ±21억 | 0 ~ 약 42억 |

동일한 비트 공간에서 **양수 표현 범위가 2배**가 됩니다.

---

## 5. 실제 장애와 어떤 관련이 있는가

### Signed/Unsigned 혼합 비교 버그

```c
int a = -1;
unsigned int b = 1;
if (a < b)   // 개발자는 참을 기대
```

자동 형변환 과정에서 `a`가 매우 큰 `unsigned` 값으로 변환되어 결과가 거짓이 될 수 있습니다.

### 언더플로우 (Underflow)

```c
unsigned int count = 0;
count--;
// 결과: 4294967295 (32bit 기준)
```

### 네트워크 길이 오류

```
패킷 길이 필드를 signed로 해석
↓
음수 발생
↓
패킷 파싱 실패
↓
통신 장애
```

### 하드웨어 레지스터 오류

```
상태 비트를 signed로 해석
↓
플래그 값 왜곡
↓
장치 동작 오류
```

## 6. 현재 문맥에서 꼭 알아야 하는 핵심 메커니즘

### 핵심 1 — 부호 비트 없음

`unsigned`에는 부호 비트(Sign Bit) 개념이 없습니다. 모든 비트가 숫자 표현에 사용됩니다.

```
4bit: 1001

1×2³ + 0×2² + 0×2¹ + 1×2⁰ = 9

(signed였다면 -7로 해석)
```

### 핵심 2 — 비트 패턴 직접 해석

| 비트 패턴 | unsigned | signed |
|---|---|---|
| `1111` | 15 | -1 |

비트 패턴은 같지만 해석 규칙이 다릅니다.

### 핵심 3 — 비트 필드에서의 중요성

```c
unsigned int flag : 1;  // 표현 가능 값: 0, 1
signed int flag : 1;    // 표현 가능 값: 0, -1
```

따라서 상태 플래그, 하드웨어 제어 비트는 대부분 `unsigned`를 사용합니다.

## 7. Linux / Runtime / K8s에서 어디서 관측되는가

### Linux Kernel

- 플래그 값, 비트맵, 권한 마스크, CPU 마스크

### Device Driver

- 장치 제어 레지스터, 인터럽트 플래그, 상태 레지스터

### 네트워크 스택

- IP 길이, 포트 번호, TCP 플래그

### 파일 시스템

- inode, 블록 번호, 파일 크기

```bash
gdb
lldb
objdump    # 같은 비트 패턴을 signed / unsigned로 다르게 출력 확인 가능
```
