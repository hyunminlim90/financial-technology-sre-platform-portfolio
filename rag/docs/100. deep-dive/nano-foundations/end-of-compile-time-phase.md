# 컴파일 타임의 종료 (End of Compile-time Phase)

> 정독: 0회

## 1. 이 기술이 무엇인가

컴파일 타임의 종료는:

> 컴파일러가 단일 소스 파일에 대한 번역 작업을 모두 끝내고 목적 파일(Object File)을 생성한 시점을 의미

```
소스 코드
↓
컴파일
↓
목적 파일 생성 완료
```

아직 실행 파일은 아니며, 링커(Linker)가 동작하기 전 단계입니다.

```
소스 프로그램 단계 종료
↓
컴파일러 작업 종료
↓
목적 파일 생성 완료
↓
링커 작업 대기
```

---

## 2. 시스템 어디에서 등장하는가

빌드 파이프라인에서 **컴파일러 영역 종료 / 링커 영역 시작**을 구분하는 경계선입니다.

```
Source Program
↓
Preprocessing
↓
Parsing
↓
Semantic Analysis
↓
Optimization
↓
Code Generation
↓
★ End of Compile-time
↓
Object File
↓
Linking
↓
Executable File
```

---

## 3. 어떤 자원에 가장 영향이 큰가

가장 직접적인 자원은 **CPU**, **Memory**, **Disk**입니다.

| 자원 | 역할 |
|------|------|
| CPU | 구문 분석, 최적화, 코드 생성 수행 |
| Memory | AST, 중간 표현(IR), 심볼 테이블, 최적화 데이터 보관 |
| Disk | `main.o`, `module.o` 등 목적 파일 생성 |

> Network 영향은 거의 없습니다.

---

## 4. 왜 중요한가

이 시점에서 프로그램의 상당 부분이 이미 결정됩니다.

아래 선언을 예로 들면:

```c
struct Config {
    int a;
    char b;
};
```

컴파일 종료 시점에 이미 다음이 결정됩니다.

- 구조체 크기
- 멤버 오프셋
- 정렬 규칙
- 패딩 위치
- CPU 명령어
- 레지스터 사용 방식

즉, **프로그램의 물리적 형태가 최초로 확정되는 시점**입니다.

---

## 5. 실제 장애와 어떤 관련이 있는가

| 장애 유형 | 원인 | 결과 |
|-----------|------|------|
| 컴파일 오류 | 문법 오류, 타입 오류 | 컴파일 종료 도달 실패 |
| ABI 불일치 | 서로 다른 ABI 기준으로 컴파일 | 링킹 오류, 런타임 Crash |
| 잘못된 최적화 | 컴파일러 버그 | 잘못된 목적 파일 생성 |
| 아키텍처 선택 오류 | ARM용으로 컴파일 후 x86 환경에서 실행 시도 | 실행 불가 |

---

## 6. 핵심 메커니즘

컴파일 종료 시점은 다음 정보들이 모두 확정되는 순간입니다.

```
비트 필드 레이아웃
↓
부호 규칙
↓
비트 위치
↓
정렬 규칙
↓
패딩 규칙
↓
기계어 생성
```

아래 선언을 예로 들면:

```c
struct Status {
    unsigned int mode : 3;
    unsigned int flag : 1;
};
```

컴파일 종료 시점에 이미 `mode` 위치, `flag` 위치, 구조체 크기, 패딩 여부가 확정됩니다.

아직 확정되지 않은 것:

- 외부 함수 주소
- 외부 라이브러리 주소
- 최종 실행 주소

이들은 링커가 처리합니다.

| 상태 | 내용 |
|------|------|
| 확정 완료 | 레이아웃, 비트 위치, 정렬, 패딩, 기계어 |
| 미확정 | 외부 함수/라이브러리 주소, 최종 실행 주소 |

> **핵심 사실:** 컴파일 종료 시점에는 레이아웃은 확정되지만, **주소 결합은 아직 끝나지 않았다.**

## 7. Linux / Runtime / K8s에서 어디서 관측되는가

### Linux

```bash
# 목적 파일 생성
gcc -c main.c
# 결과: main.o

# 목적 파일 확인
file main.o
# 출력 예: ELF 64-bit relocatable

# 심볼 확인
nm main.o

# 재배치 정보 확인
readelf -r main.o

# 섹션 확인
readelf -S main.o
```

### Kubernetes

Kubernetes 런타임에서는 거의 관측되지 않습니다. 이 단계는 빌드 환경, CI 서버, 컴파일 서버에서만 존재하기 때문입니다.
