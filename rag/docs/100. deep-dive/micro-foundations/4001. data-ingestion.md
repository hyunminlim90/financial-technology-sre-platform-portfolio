# Data Ingestion (데이터 수집)

> 정독: 1회

## 1. 무엇인가

데이터 수집(Data Ingestion)은 다양한 데이터 소스로부터 생성된 데이터를 수집하여 데이터 시스템으로 전달하는 과정이다.

데이터 수집의 목적은 데이터를 안전하고 신뢰성 있게 저장 및 처리 가능한 환경으로 이동시키는 것이다.

데이터 수집은 데이터 처리 생명주기의 시작 단계이다.

주요 목적은 다음과 같다.

- 데이터 수집
- 데이터 전달
- 데이터 적재
- 데이터 처리 준비
- 데이터 품질 확보

## 2. 시스템 어디에서 등장하는가

데이터 수집은 데이터가 생성된 이후 가장 먼저 수행되는 과정이다.

전체 흐름은 다음과 같다.

```
Data Source
      ↓
Data Ingestion
      ↓
Data Processing
      ↓
Data Storage
      ↓
Data Analysis
```

데이터 소스는 다양할 수 있다.

- 사용자 요청
- 애플리케이션
- 데이터베이스
- 파일
- 센서
- 외부 시스템
- 로그
- 이벤트

수집된 데이터는 이후 저장, 처리, 분석 과정으로 전달된다.

## 3. 어떤 자원(CPU/Memory/Network/Disk)에 가장 영향이 큰가

데이터 수집은 시스템의 모든 주요 자원을 사용한다.

| 자원 | 영향 |
|---|---|
| CPU | 데이터 변환 및 검증 |
| Memory | 버퍼 및 임시 저장 |
| Network | 데이터 전송 |
| Disk | 임시 저장 및 영구 저장 |

### CPU

대표 작업

- 데이터 검증
- 데이터 변환
- 압축
- 암호화

### Memory

대표 작업

- 버퍼
- 큐
- 임시 데이터 저장

### Network

대표 작업

- 데이터 전송
- 노드 간 통신
- 원격 시스템 연결

### Disk

대표 작업

- 임시 파일 저장
- 로그 기록
- 최종 데이터 저장

## 4. 왜 중요한가

모든 데이터 처리는 데이터 수집으로부터 시작된다.

수집 단계의 품질은 이후 모든 데이터 처리 품질에 영향을 준다.

다음과 같은 품질 특성이 중요하다.

- 신뢰성
- 가용성
- 확장성
- 처리량
- 지연시간
- 데이터 무결성

수집 과정에서 데이터가 유실되거나 중복되면 이후 단계에서 이를 복구하기 어려운 경우가 많다.

## 5. 실제 장애와 어떤 관련이 있는가

운영 환경에서는 데이터 수집 단계에서 다양한 장애가 발생할 수 있다.

### CPU 관련

**원인**

- 대량 데이터 변환
- 복잡한 검증
- 과도한 데이터 처리

**결과**

- CPU Usage 증가
- 처리 지연
- 처리량 감소

### Memory 관련

**원인**

- 버퍼 부족
- 큐 적체
- 메모리 부족

**결과**

- Memory Usage 증가
- 데이터 처리 지연
- 수집 중단

### Network 관련

**원인**

- 대량 데이터 전송
- 네트워크 지연
- 패킷 손실

**결과**

- Timeout
- 전송 실패
- 수집 지연

### Disk 관련

**원인**

- 저장 공간 부족
- 과도한 로그 기록
- 디스크 처리량 부족

**결과**

- Disk I/O 증가
- 저장 실패
- 응답시간 증가

### 데이터 관련

**원인**

- 중복 데이터
- 누락 데이터
- 손상된 데이터
- 순서 변경

**결과**

- 데이터 무결성 저하
- 분석 오류
- 서비스 품질 저하

## 6. 현재 문맥에서 꼭 알아야 하는 핵심 메커니즘만 설명

E2E SRE 문서를 읽는 관점에서는 데이터 수집을 다음 다섯 단계로 이해하면 충분하다.

### 데이터 생성

데이터가 최초로 생성된다.

- Application
- User
- Device
- System

### 데이터 수집

데이터를 읽어온다.

- Read
- Receive
- Subscribe

### 데이터 검증

수집된 데이터를 확인한다.

- Format Validation
- Integrity Check
- Duplicate Check

### 데이터 전달

다음 시스템으로 전달한다.

- Transfer
- Queue
- Buffer

### 데이터 적재

최종 저장소에 기록한다.

- Storage
- Database
- Data Lake

### 핵심 흐름

```
Generate
      ↓
Collect
      ↓
Validate
      ↓
Transfer
      ↓
Store
```

데이터 수집 방식은 일반적으로 다음 두 가지로 구분된다.

**Batch Ingestion**

일정 주기로 데이터를 모아서 처리한다.

```
Collect
      ↓
Store
```

**Streaming Ingestion**

데이터 발생과 동시에 지속적으로 처리한다.

```
Generate
      ↓
Collect
      ↓
Transfer
      ↓
Store
```

E2E SRE 관점에서는

> 데이터를 어디에서 가져오는가

보다

- 데이터가 얼마나 빠르게 들어오는가
- 얼마나 안정적으로 전달되는가
- 유실 없이 저장되는가
- 과부하 상황에서도 계속 처리되는가

를 이해하는 것이 중요하다.

## 7. Linux / Runtime / Kubernetes 에서 어디서 관측되는가

데이터 수집 과정은 운영 환경에서 다양한 지표로 관측된다.

### Linux

**관측 대상**

- CPU Usage
- Memory Usage
- Network Throughput
- Disk I/O
- Process 상태

**대표 도구**

```
top
vmstat
iostat
sar
ss
iftop
```

### Runtime

**관측 대상**

- Ingestion Rate
- Processing Latency
- Queue Length
- Buffer Usage
- Error Rate
- Retry Count

**대표 자료**

- Metrics
- Logs
- Traces

### Kubernetes

**관측 대상**

- Pod 상태
- CPU Usage
- Memory Usage
- Network Traffic
- Restart Count
- Autoscaling 상태

**대표 명령**

```
kubectl get
kubectl describe
kubectl logs
kubectl top
```

## E2E SRE 문서 관점 핵심 정리

데이터 수집은

> 다양한 데이터 소스로부터 생성된 데이터를 데이터 시스템으로 전달하는 과정이다.

핵심 기능은

- Collect
- Validate
- Transfer
- Buffer
- Store

이다.

E2E SRE 관점에서는

```
Data Source
      ↓
Data Ingestion
      ↓
CPU / Memory / Network / Disk 사용 특성
      ↓
Data Processing
      ↓
Observability
```

의 흐름으로 이해하면 된다.

운영 환경에서 관측되는

- 수집 지연
- Queue 적체
- Buffer 부족
- Network 지연
- Disk I/O 증가
- Retry 증가
- 데이터 유실

등은 대부분 데이터 수집 계층의 처리량과 자원 사용 한계를 초과할 때 발생한다.

데이터 수집의 핵심은 데이터를 단순히 이동시키는 것이 아니라, 다양한 데이터 소스로부터 생성된 데이터를 유실 없이 안정적으로 수집하여 이후 저장과 처리가 가능한 형태로 전달하는 것이다.
