# Linux Container (리눅스 컨테이너)

> 정독: 1회

## 1. 무엇인가

리눅스 컨테이너(Linux Container)는 하나의 리눅스 커널을 공유하면서 애플리케이션을 서로 독립된 실행 환경에서 실행할 수 있도록 제공하는 운영체제 수준의 가상화 기술이다.

컨테이너는 운영체제 전체를 가상화하는 것이 아니라, 애플리케이션 실행에 필요한 프로세스와 자원을 격리하여 실행한다.

리눅스 컨테이너의 목적은 다음과 같다.

- 애플리케이션 격리
- 실행 환경 일관성 제공
- 자원 효율성 향상
- 배포 표준화
- 운영 자동화 지원

리눅스 컨테이너는 애플리케이션 실행 환경을 독립적으로 제공하면서도 호스트 운영체제의 커널을 공유한다.

## 2. 시스템 어디에서 등장하는가

리눅스 컨테이너는 운영체제와 애플리케이션 사이에서 실행 환경을 제공한다.

전체 구조는 다음과 같다.

```
Application
      ↓
Container
      ↓
Container Runtime
      ↓
Linux Kernel
      ↓
Hardware
```

컨테이너 내부에는 일반적으로 다음 요소가 포함된다.

- 애플리케이션
- 실행 파일
- 라이브러리
- 설정 파일
- 환경 변수

컨테이너는 하나의 리눅스 커널 위에서 여러 개가 동시에 실행될 수 있다.

## 3. 어떤 자원(CPU/Memory/Network/Disk)에 가장 영향이 큰가

리눅스 컨테이너는 시스템의 모든 주요 자원을 사용하며, 커널이 이를 관리한다.

| 자원 | 영향 |
|---|---|
| CPU | 프로세스 실행 및 스케줄링 |
| Memory | 프로세스 메모리 사용 |
| Network | 네트워크 격리 및 통신 |
| Disk | 이미지 및 파일시스템 관리 |

### CPU

대표 작업

- 프로세스 실행
- CPU Scheduling
- CPU Limit

### Memory

대표 작업

- Memory Allocation
- Memory Limit
- OOM 관리

### Network

대표 작업

- Virtual Network
- Network Namespace
- Packet 전달

### Disk

대표 작업

- Container Image
- Layer 관리
- Overlay Filesystem
- Volume

## 4. 왜 중요한가

리눅스 컨테이너는 동일한 실행 환경을 다양한 서버에서 일관되게 제공한다.

또한 운영체제 수준의 격리를 통해 여러 애플리케이션을 하나의 호스트에서 독립적으로 실행할 수 있다.

다음과 같은 품질 특성에 영향을 준다.

- 배포 일관성
- 자원 효율성
- 확장성
- 격리성
- 이식성

리눅스 컨테이너는 클라우드 환경과 대규모 분산 시스템의 기본 실행 단위로 사용된다.

## 5. 실제 장애와 어떤 관련이 있는가

운영 환경에서는 컨테이너 실행 환경과 커널 자원 관리 과정에서 다양한 문제가 발생할 수 있다.

### CPU 관련

**원인**

- CPU Limit 부족
- CPU 경쟁
- 프로세스 과부하

**결과**

- CPU Throttling
- Latency 증가
- 처리량 감소

### Memory 관련

**원인**

- Memory Limit 초과
- 메모리 부족
- 메모리 경쟁

**결과**

- OOMKill
- Container Restart
- 서비스 중단

### Network 관련

**원인**

- Network Namespace 오류
- 가상 네트워크 장애
- DNS 문제

**결과**

- Connection Failure
- Timeout
- Packet Loss

### Disk 관련

**원인**

- Image Pull 실패
- Overlay Filesystem 문제
- Disk Space 부족

**결과**

- Container 생성 실패
- Image Pull Error
- Disk I/O 증가

### 격리 관련

**원인**

- Namespace 설정 오류
- cgroup 설정 오류
- 권한 설정 오류

**결과**

- 자원 충돌
- 권한 문제
- 실행 실패

## 6. 현재 문맥에서 꼭 알아야 하는 핵심 메커니즘만 설명

E2E SRE 문서를 읽는 관점에서는 리눅스 컨테이너를 다음 다섯 가지 핵심 메커니즘으로 이해하면 충분하다.

### Namespace

프로세스가 서로 독립된 실행 환경을 갖도록 한다.

격리 대상

- PID
- Network
- Mount
- IPC
- User
- UTS

### cgroups

컨테이너가 사용할 수 있는 시스템 자원을 제한하고 관리한다.

관리 대상

- CPU
- Memory
- Disk I/O
- Network
- Process 수

### Image

컨테이너 실행에 필요한 파일과 설정을 포함하는 실행 단위이다.

- Application
- Library
- Configuration

### Container Runtime

이미지를 실행하여 실제 컨테이너를 생성한다.

```
Image
      ↓
Runtime
      ↓
Container
```

### Container Lifecycle

컨테이너는 생성부터 종료까지 일정한 생명주기를 가진다.

```
Create
      ↓
Start
      ↓
Running
      ↓
Stop
      ↓
Remove
```

### 핵심 실행 흐름

```
Image
      ↓
Container Runtime
      ↓
Linux Kernel
      ↓
Process Execution
```

E2E SRE 관점에서는

> 컨테이너 내부에 무엇이 있는가

보다

- 컨테이너가 어떻게 격리되는가
- 어떻게 자원을 사용하는가
- 커널이 어떻게 관리하는가
- 어떻게 실행되고 종료되는가

를 이해하는 것이 중요하다.

## 7. Linux / Runtime / Kubernetes에서 어디서 관측되는가

리눅스 컨테이너는 운영체제와 컨테이너 런타임을 통해 관측된다.

### Linux

**관측 대상**

- Process
- Namespace
- cgroups
- CPU Usage
- Memory Usage
- Disk I/O
- Network Usage

**대표 도구**

```
top
ps
vmstat
iostat
sar
ss

```

### Runtime

**관측 대상**

- Container 상태

- Runtime Event
- Resource Usage

**대표 자료**

- Metrics
- Logs
- Container Events

### Kubernetes

**관측 대상**


## E2E SRE 문서 관점 핵심 정리

리눅스 컨테이너는

> 하나의 리눅스 커널을 공유하면서 애플리케이션을 독립된 실행 환경에서 실행하는 운영체제 수준의 가상화 기술이다.

핵심 메커니즘은

- Namespace
- cgroups
- Image
- Container Runtime
- Container Lifecycle

이다.

E2E SRE 관점에서는

```
Application
      ↓
Container
      ↓
Linux Kernel
      ↓
CPU / Memory / Network / Disk 사용 특성
      ↓
Observability
```

의 흐름으로 이해하면 된다.

운영 환경에서 관측되는

- OOMKill
- CPU Throttling
- Image Pull 실패
- Container Restart
- Network Namespace 오류
- Disk I/O 증가
- Container 생성 실패

등은 대부분 리눅스 커널의 자원 관리, Namespace 또는 cgroups 설정, 컨테이너 런타임의 동작과 관련된 문제에서 발생한다.

리눅스 컨테이너의 핵심은 운영체제를 가상화하는 것이 아니라, 하나의 리눅스 커널 위에서 프로세스를 격리하고 자원을 제어하여 독립적인 실행 환경을 제공하는 것이다.
