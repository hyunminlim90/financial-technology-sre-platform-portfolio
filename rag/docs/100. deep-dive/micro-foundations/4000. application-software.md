# Application Software (애플리케이션 소프트웨어)

> 정독: 1회

## 1. 무엇인가

애플리케이션 소프트웨어(Application Software)는 **운영체제** 위에서 실행되며, 사용자 또는 조직이 필요한 업무와 기능을 수행하도록 제공하는 소프트웨어이다.

애플리케이션 소프트웨어는 사용자의 요청을 처리하고, 데이터를 이용하여 원하는 결과를 제공하는 역할을 수행한다.

주요 목적은 다음과 같다.

- 사용자 요청 처리
- 비즈니스 기능 제공
- 데이터 처리
- 서비스 제공
- 업무 자동화

애플리케이션 소프트웨어는 시스템 소프트웨어가 제공하는 실행 환경을 이용하여 동작한다.

## 2. 시스템 어디에서 등장하는가

애플리케이션 소프트웨어는 운영체제 위에서 실행되며, 사용자와 시스템을 연결하는 역할을 수행한다.

전체 구조는 다음과 같다.

```
User
      ↓
Application Software
      ↓
Operating System
      ↓
Hardware
```

애플리케이션은 일반적으로 다음 구성 요소와 함께 동작한다.

- User Interface
- Business Logic
- Data Access
- External Service Interface

전체 처리 흐름은 다음과 같다.

```
User Request
      ↓
Application Software
      ↓
Business Processing
      ↓
Data Access
      ↓
Response
```

## 3. 어떤 자원(CPU/Memory/Network/Disk)에 가장 영향이 큰가

애플리케이션 소프트웨어는 시스템의 모든 주요 자원을 사용한다.

| 자원 | 영향 |
|---|---|
| CPU | 비즈니스 로직 실행 및 계산 |
| Memory | 프로그램 실행 및 데이터 관리 |
| Network | 외부 시스템 및 사용자 통신 |
| Disk | 파일 및 데이터 저장 |

### CPU

대표 작업

- 비즈니스 로직 실행
- 연산 처리
- 요청 처리

### Memory

대표 작업

- 프로그램 실행
- 객체 관리
- 캐시
- 버퍼

### Network

대표 작업

- 사용자 요청 처리
- 외부 시스템 통신
- 데이터 전송

### Disk

대표 작업

- 파일 접근
- 로그 기록
- 설정 파일 관리

## 4. 왜 중요한가

사용자가 직접 사용하는 기능은 대부분 애플리케이션 소프트웨어에서 제공된다.

애플리케이션 소프트웨어는 다음과 같은 품질 특성에 영향을 준다.

- 기능성
- 성능
- 신뢰성
- 가용성
- 확장성
- 유지보수성

애플리케이션의 품질은 사용자 경험과 서비스 품질을 직접 결정한다.

## 5. 실제 장애와 어떤 관련이 있는가

운영 환경에서는 애플리케이션 내부와 외부 연동 과정에서 다양한 문제가 발생할 수 있다.

### CPU 관련

**원인**

- 복잡한 연산
- 무한 반복
- 비효율적인 알고리즘

**결과**

- CPU Usage 증가
- Latency 증가
- 처리량 감소

### Memory 관련

**원인**

- Memory Leak
- 객체 증가
- 캐시 과다 사용

**결과**

- Memory Usage 증가
- OOM
- 프로세스 종료

### Network 관련

**원인**

- 외부 서비스 지연
- 네트워크 장애
- 연결 실패

**결과**

- Timeout
- Connection Failure
- 응답 지연

### Disk 관련

**원인**

- 로그 증가
- 파일 접근 증가
- 저장 공간 부족

**결과**

- Disk I/O 증가
- 저장 실패
- 응답시간 증가

### 애플리케이션 관련

**원인**

- 예외 처리 오류
- 설정 오류
- 프로세스 종료
- 배포 오류

**결과**

- 서비스 장애
- 오류 응답 증가
- 기능 실패

## 6. 현재 문맥에서 꼭 알아야 하는 핵심 메커니즘만 설명

E2E SRE 문서를 읽는 관점에서는 애플리케이션 소프트웨어를 다음 여섯 가지 기능으로 이해하면 충분하다.

### 사용자 요청 처리

사용자의 요청을 수신한다.

- Receive Request

### 비즈니스 처리

요청에 대한 업무 로직을 수행한다.

- Business Logic

### 데이터 접근

필요한 데이터를 조회하거나 저장한다.

- Read
- Write
- Update
- Delete

### 외부 시스템 연동

다른 시스템과 데이터를 교환한다.

- API
- Message
- Service

### 결과 생성

처리 결과를 생성한다.

- Response
- Output

### 오류 처리

예외 상황을 처리하고 안정성을 유지한다.

- Exception
- Retry
- Recovery

### 핵심 처리 흐름

```
Request
      ↓
Business Logic
      ↓
Data Processing
      ↓
Response
```

- 요청이 어떻게 처리되는가
- 데이터와 어떻게 연동되는가

를 이해하는 것이 중요하다.

## E2E SRE 문서 관점 핵심 정리

애플리케이션 소프트웨어는

> 운영체제 위에서 실행되며 사용자의 요청을 처리하고 비즈니스 기능을 수행하는 응용 소프트웨어이다.

핵심 기능은

- Request Processing
- Business Logic
- Data Access
- External Communication
- Response Generation
- Error Handling

이다.

E2E SRE 관점에서는

```
User
      ↓
Application Software
      ↓
Operating System
      ↓
CPU / Memory / Network / Disk 사용 특성
      ↓
Observability
```

의 흐름으로 이해하면 된다.

운영 환경에서 관측되는

- CPU Usage 증가
- Memory Leak
- OOM
- Timeout
- Application Error
- Process 종료
- Restart 증가

등은 대부분 애플리케이션 내부의 처리 과정, 외부 시스템 연동 또는 자원 사용 문제에서 발생한다.

애플리케이션 소프트웨어의 핵심은 사용자의 요청을 처리하여 필요한 기능을 제공하고, 운영체제가 제공하는 실행 환경을 이용하여 데이터를 처리하고 서비스를 제공하는 것이다.
