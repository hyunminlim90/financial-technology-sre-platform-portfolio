# 타깃 운영체제 (Target Operating System / Target OS)

> 정독: 0회

## 1. 이 기술이 무엇인가

타깃 운영체제(Target OS)는:

> 컴파일된 프로그램이 실제로 실행될 운영체제

타깃 프로세서가 "어떤 CPU에서 실행되는가"를 결정한다면  

타깃 운영체제는 **"어떤 운영체제 규칙 아래에서 실행되는가"** 를 결정합니다.  

컴파일러는 프로그램을 생성할 때 CPU만 고려하지 않습니다. 다음도 함께 고려합니다.

- CPU 아키텍처
- 운영체제
- ABI
- 실행 파일 포맷
- 시스템 콜 인터페이스

```
Target CPU
+
Target OS
```

이 조합이 실제 실행 환경을 결정합니다.

---

## 2. 시스템 어디에서 등장하는가

```
소스 프로그램
↓
컴파일
↓
타깃 OS용 실행 파일 생성
↓
OS Loader 적재
↓
프로세스 생성
↓
실행
```

특히 다음 과정에 직접 관여합니다.

- 실행 파일 생성
- 프로세스 생성
- 메모리 할당
- 시스템 콜 수행

---

## 3. 어떤 자원에 가장 영향이 큰가

가장 큰 영향은 **Memory**와 **Disk**입니다.

| 자원 | 운영체제가 결정하는 것 |
|------|----------------------|
| Memory | 가상 메모리, 프로세스 주소 공간, 페이지 매핑, 메모리 보호 |
| Disk | 실행 파일 포맷, 파일 시스템 인터페이스, 동적 라이브러리 로딩 |

> CPU는 주로 타깃 프로세서가 결정하고, Network는 운영체제 네트워크 스택의 영향을 받습니다.

---

## 4. 왜 중요한가

같은 CPU라도 운영체제마다 실행 파일 형식이 다릅니다.

| 운영체제 | 실행 파일 포맷 |
|----------|---------------|
| Windows | PE |
| Linux | ELF |
| macOS | Mach-O |

따라서 같은 소스 코드, 같은 CPU라도 다음이 달라집니다.

- 실행 파일 구조
- 라이브러리 연결 방식
- 시스템 호출 방식

또한 운영체제는 메모리 할당, 프로세스/스레드 생성, 파일 접근, 네트워크 접근을 모두 관리합니다.

---

## 5. 실제 장애와 어떤 관련이 있는가

| 장애 유형 | 원인 | 결과 |
|-----------|------|------|
| 실행 파일 포맷 불일치 | Windows PE 파일을 Linux에서 실행 시도 | `Exec format error` |
| 라이브러리 불일치 | 빌드 환경 glibc 2.38 → 실행 환경 glibc 2.28 | 프로그램 시작 실패 |
| 시스템 콜 차이 | OS마다 프로세스 생성·파일 접근·네트워크 처리 방식 상이 | 포팅 실패, 런타임 오류 |
| 메모리 정책 차이 | OS별 페이지 크기·주소 공간 배치·스택 크기 상이 | 성능 차이, OOM, Crash |

## 6. 핵심 메커니즘

현재 비트 필드 문맥에서는 다음 순서가 중요합니다.

```
타깃 프로세서
↓
타깃 운영체제
↓
ABI
↓
컴파일러
↓
비트 필드 레이아웃
```

많은 경우 비트 필드 배치를 CPU만 결정한다고 생각하지만, 실제로는 **CPU + 운영체제 + ABI** 조합이 결정합니다.

아래 선언을 예로 들면:

```c
struct Status {
    unsigned int mode : 3;
    unsigned int flag : 1;
};
```

컴파일러는 타깃 CPU, 타깃 OS, ABI 정보를 사용하여 정렬, 패딩, 멤버 배치, 구조체 크기를 결정합니다.

> **핵심 사실:** 비트 필드의 실제 메모리 구조는 언어 문법이 아니라  
> **타깃 플랫폼 (CPU + OS + ABI)** 이 결정한다.

## 7. Linux / Runtime / K8s에서 어디서 관측되는가

### Linux

```bash
# 운영체제 확인
uname -s        # 출력 예: Linux

# 커널 버전 확인
uname -r

# 상세 OS 정보
cat /etc/os-release

# 실행 파일 포맷 확인
file myapp      # 출력 예: ELF 64-bit executable

# 동적 라이브러리 확인
ldd myapp

# ABI 확인
readelf -h myapp
```

### Kubernetes

```bash
# 컨테이너 내부 OS 확인
kubectl exec -it POD -- cat /etc/os-release
```

실무에서는 OS 버전 차이, glibc 차이, 커널 차이로 인해 **개발 환경에서는 정상 / 운영 환경에서는 실패**하는 문제가 자주 발생합니다.
