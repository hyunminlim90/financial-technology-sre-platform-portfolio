# 자바 프로그래밍 언어 사양(The Java Language Specification, JLS)

> 정독: 0회

## 1. 이 기술이 무엇인가

JLS(The Java Language Specification)는:

> **자바 언어의 공식 표준 명세**

**정의 대상:**

- 문법(Syntax)
- 타입 시스템(Type System)
- 클래스 구조
- 메모리 가시성 규칙
- 스레드 동작
- 예외 처리
- 연산 의미
- 컴파일 규칙

> **핵심:** "자바 코드가 어떻게 해석되고 동작해야 하는가"를 전 세계적으로 동일하게 규정하는 것

---

## 2. 시스템 어디에서 등장하는가

JLS는 자바 생태계 전반의 기반입니다.

| 영역 | 역할 |
|------|------|
| 컴파일러 | 문법 검증 기준 |
| IDE | 코드 분석 기준 |
| JVM | 실행 의미 기준 |
| 라이브러리 | 타입 호환 기준 |
| 멀티스레드 시스템 | 메모리 모델 기준 |
| 런타임 | 객체/호출 의미 기준 |

**자바 시스템 전체가 JLS 위에서 움직입니다.**

---

## 3. 어떤 자원(CPU/Memory/Network/Disk)에 가장 영향이 큰가

JLS는 직접 하드웨어를 제어하지는 않지만, 언어의 실행 의미를 정의하기 때문에 특히 **CPU와 메모리 동작에 매우 큰 영향**을 줍니다.

### CPU

JLS는 실행 순서, 연산 의미, 스레드 동기화, happens-before 관계 등을 정의하며, 이는 CPU 명령 재정렬과 직접 연결됩니다.

### Memory

가장 중요한 영역입니다. JLS의 Java Memory Model(JMM)은 메모리 가시성, 공유 변수 접근, `volatile`, `synchronized` 등을 정의하며, 멀티코어 시스템 안정성의 핵심입니다.

### Network / Disk

직접 영향은 적지만, 런타임 의미와 예외 처리 구조를 통해 간접적으로 영향을 줍니다.

---

## 4. 왜 중요한가

JLS가 없다면:

- 컴파일러마다 결과가 달라지고
- JVM마다 동작이 달라지고
- 멀티스레드 결과가 달라지고
- 플랫폼 간 호환성이 깨집니다.

즉, 자바의 핵심 목표인 **플랫폼 독립성**, **실행 일관성**, **타입 안정성**을 보장할 수 없습니다.

---

## 5. 실제 장애와 어떤 관련이 있는가

실제 장애는 종종 **JLS 및 메모리 모델 이해 부족**에서 발생합니다.

| 장애 | 원인 |
|------|------|
| Race Condition | 메모리 가시성 오해 |
| Deadlock | synchronized 오용 |
| 데이터 불일치 | happens-before 위반 |
| ClassCast 오류 | 타입 규칙 위반 |
| 런타임 예외 | 언어 의미 오해 |
| 플랫폼별 차이 | Undefined Behavior 가정 |

특히 멀티스레드 환경에서는 **JLS의 Java Memory Model 이해가 매우 중요**합니다.

## 6. 핵심 메커니즘

### (1) 문법(Syntax) 정의

JLS는 **"어떤 코드가 올바른 자바 코드인가"** 를 정의합니다.

- 클래스 선언
- 변수 선언
- 제어문
- 메서드 구조

등의 규칙을 명세하며, 컴파일러는 이 규칙을 기준으로 코드를 분석합니다.

### (2) 타입 시스템(Type System)

**핵심 목적:** 잘못된 연산 방지, 메모리 안정성 보장, 런타임 오류 감소

정의 대상:

- 타입 변환 규칙
- 상속 관계
- Generic 의미
- 접근 제한

### (3) Java Memory Model (JMM)

가장 중요한 영역 중 하나입니다. JLS는 멀티스레드 메모리 동작을 정의합니다.

| 개념 | 의미 |
|------|------|
| Visibility | 값 변경 가시성 |
| Ordering | 실행 순서 보장 |
| Atomicity | 원자성 보장 |
| Happens-before | 메모리 동기화 규칙 |

현대 CPU는 캐시, 명령 재정렬, 병렬 실행을 수행하기 때문에 언어 차원의 메모리 규칙이 반드시 필요합니다.

### (4) 바이트코드 의미 정의

JLS는 소스코드가 어떤 의미를 가져야 하는지를 정의합니다. 이 의미를 기반으로 컴파일러, JVM, JIT가 바이트코드를 생성하고 실행합니다.

```
JLS → 컴파일 규칙 → Bytecode → Runtime
```

### (5) 플랫폼 독립성 보장

JLS는 특정 CPU에 종속되지 않습니다. x86, ARM, RISC-V 환경에서도 동일한 언어 의미를 유지하며, 플랫폼별 차이는 **JVM 구현체가 흡수**합니다.

## 7. Linux / Runtime / K8s에서 어디서 관측되는가

### Linux

직접 JLS는 보이지 않지만 JVM 실행 동작으로 관측됩니다.

| 관측 대상 | 의미 |
|----------|------|
| Thread 상태 | JMM 영향 |
| CPU Usage | 실행 모델 |
| Memory Layout | 객체 모델 |
| Lock 상태 | synchronized 영향 |

### Runtime

가장 직접적으로 나타납니다.

| 영역 | 의미 |
|------|------|
| Bytecode | JLS 기반 |
| Class Loader | 타입 규칙 |
| JIT | 실행 의미 최적화 |
| GC | 객체 모델 기반 |
| Thread Sync | Memory Model 적용 |

### Kubernetes

K8s에서는 런타임 레벨로 드러납니다.

| 대상 | 의미 |
|------|------|
| CPU Limit | Thread 실행 영향 |
| Memory Limit | Heap 구조 영향 |
| OOMKill | 메모리 모델 영향 |
| Thread Dump | 동기화 상태 |
| GC Pause | 객체 구조 영향 |
