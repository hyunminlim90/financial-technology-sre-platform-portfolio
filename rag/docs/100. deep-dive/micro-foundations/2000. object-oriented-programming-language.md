# Object-Oriented Programming Language (객체 지향 프로그래밍 언어)

> 정독: 1회

## 1. 무엇인가

객체 지향 프로그래밍 언어(Object-Oriented Programming Language, OOPL)는 **프로그램**을 객체(Object)의 생성과 상호작용을 중심으로 구성하는 프로그래밍 언어이다.

객체는 데이터와 데이터를 처리하는 기능을 하나의 단위로 구성한 실행 요소이다.

객체 지향 프로그래밍의 목적은 다음과 같다.

- 데이터와 기능의 통합
- 역할 분리
- 코드 재사용
- 확장성 향상
- 유지보수성 향상

객체 지향은 프로그램을 독립적인 구성 요소들의 협력 구조로 구현하는 프로그래밍 방식이다.

## 2. 시스템 어디에서 등장하는가

객체 지향은 구현 단계에서 프로그램 구조를 구성하는 방식이다.

```
Requirements
      ↓
Design
      ↓
Object-Oriented Modeling
      ↓
Implementation
      ↓
Runtime
```

객체 지향은 다음 요소를 구성하는 데 사용된다.

- 객체
- 클래스
- 인터페이스
- 모듈
- 컴포넌트

실행 시에는 다음과 같이 동작한다.

```
Object
      ↓
Method Invocation
      ↓
Object Interaction
      ↓
Program Execution
```

## 3. 어떤 자원(CPU/Memory/Network/Disk)에 가장 영향이 큰가

객체 지향은 시스템의 모든 자원 사용 방식에 영향을 준다.

| 자원 | 영향 |
|---|---|
| CPU | 객체 간 호출, 메서드 실행 |
| Memory | 객체 생성 및 생명주기 |
| Network | 객체 기반 데이터 교환 |
| Disk | 객체 직렬화 및 데이터 저장 |

### CPU

객체의 메서드 실행 과정에서 CPU를 사용한다.

**대표 요소**
- 메서드 호출
- 동적 디스패치
- 다형성 처리

### Memory

객체는 실행 중 메모리에 생성되고 관리된다.

**대표 요소**
- 객체 생성
- 객체 참조
- 객체 제거

### Network

객체의 상태는 네트워크를 통해 전달될 수 있다.

**대표 요소**
- 데이터 직렬화
- 데이터 역직렬화
- 원격 호출

### Disk

객체 정보는 저장 장치에 기록될 수 있다.

**대표 요소**
- 파일 저장
- 데이터 저장
- 로그 기록

## 4. 왜 중요한가

객체 지향은 프로그램을 변경하기 쉬운 구조로 만드는 것을 목표로 한다.

다음과 같은 품질 특성에 영향을 준다.

- 확장성
- 유지보수성
- 재사용성
- 가독성
- 변경 용이성

객체 간 역할과 책임을 명확히 분리하면 변경 범위를 제한할 수 있다.

## 5. 실제 장애와 어떤 관련이 있는가

객체 지향 자체가 장애를 발생시키는 것은 아니다.

그러나 객체 구조와 설계 방식은 운영 특성과 장애 특성에 영향을 준다.

### Memory 관련

**원인**
- 과도한 객체 생성
- 객체 참조 유지
- 객체 생명주기 관리 실패

**결과**
- Memory Usage 증가
- Memory Leak
- GC 증가

### CPU 관련

**원인**
- 불필요한 객체 생성
- 복잡한 호출 구조
- 과도한 연산

**결과**
- CPU Usage 증가
- 응답시간 증가

### Concurrency 관련

**원인**
- 공유 객체 접근
- 동기화 설계 오류

**결과**
- Deadlock
- Lock Contention
- Race Condition

### 유지보수 관련

**원인**
- 강한 의존성
- 역할 혼합
- 낮은 응집도

**결과**
- 변경 영향 범위 증가
- 결함 발생 가능성 증가
- 테스트 어려움

## 6. 현재 문맥에서 꼭 알아야 하는 핵심 메커니즘만 설명

E2E SRE 문서를 읽는 관점에서는 객체 지향을 다음 다섯 가지 개념으로 이해하면 충분하다.

### 클래스(Class)

객체를 생성하기 위한 정의이다.

- 속성
- 행위
- 관계

### 객체(Object)

실행 중 메모리에 존재하는 구성 요소이다.

- 상태
- 동작
- 참조

### 캡슐화(Encapsulation)

데이터와 기능을 하나의 단위로 구성하고 내부 구현을 외부와 분리한다.

- 데이터 보호
- 인터페이스 제공

### 상속(Inheritance)

기존 구조를 기반으로 새로운 구조를 정의한다.

- 기능 재사용
- 공통 기능 확장

### 다형성(Polymorphism)

동일한 인터페이스를 다양한 구현으로 사용할 수 있도록 한다.

- 인터페이스
- 구현 분리
- 동적 선택

### 핵심 실행 흐름

```
Class
      ↓
Object Creation
      ↓
Method Execution
      ↓
Object Interaction
      ↓
Program Execution
```

E2E SRE 관점에서는

- 객체를 어떻게 설계했는가

보다

- 객체가 실행 중 메모리를 어떻게 사용하는가
- 서로 어떻게 의존하는가
- 어떻게 상호작용하는가

를 이해하는 것이 중요하다.

## 7. Linux / Runtime / Kubernetes 에서 어디서 관측되는가

객체 지향 자체는 Linux나 Kubernetes에서 직접 관측되지 않는다.

객체가 실행되면서 발생하는 런타임 동작이 관측된다.

### Linux

**관측 대상**
- Process
- Thread
- CPU Usage
- Memory Usage

**대표 도구**
```
top
ps
vmstat
sar
```

### Runtime

**관측 대상**
- 객체 생성 수
- Heap 사용량
- GC
- Thread
- Exception

**대표 자료**
- Metrics
- Logs
- Heap Dump
- Thread Dump
- Runtime Profiling

### Kubernetes

**관측 대상**
- Container Memory
- CPU Usage
- Restart Count
- Health Check

**대표 명령**
```
kubectl top
kubectl logs
kubectl describe
```

## E2E SRE 문서 관점 핵심 정리

객체 지향 프로그래밍 언어는 프로그램을 객체의 생성과 상호작용으로 구성하는 프로그래밍 방식이다.

핵심 개념은

- Class
- Object
- Encapsulation
- Inheritance
- Polymorphism

이다.

E2E SRE 관점에서는

```
Object-Oriented Design
      ↓
Object Creation
      ↓
Runtime Behavior
      ↓
CPU / Memory / Thread / Network / Disk 사용 특성
      ↓
Observability
```

의 흐름으로 이해하면 된다.

운영 환경에서 관측되는

- 객체 생성 증가
- Heap 사용량 증가
- GC 증가
- Memory Leak
- CPU 사용률 증가
- Thread 증가

등은 객체 지향 자체의 문제가 아니라

- 객체의 생명주기
- 객체 간 의존성
- 객체 생성 및 참조 관리

구현 방식의 결과로 나타난다.

따라서 객체 지향 기반 시스템을 분석할 때는 문법보다 객체 구조와 실행 시 자원 사용 특성을 이해하는 것이 중요하다.
