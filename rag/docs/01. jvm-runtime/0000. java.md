# Java (자바)

> 정독: 1회

## 1. 무엇인가

자바(Java)는 「객체 지향 프로그래밍 언어」 이자, 바이트코드(Bytecode)를 기반으로 다양한 운영체제에서 실행할 수 있도록 설계된 소프트웨어 플랫폼이다.

자바 플랫폼은 일반적으로 다음 구성 요소로 이루어진다.

- Java Source Code
- Compiler
- Bytecode
- Java Virtual Machine (JVM)
- Runtime Libraries

자바의 목적은 운영체제에 독립적인 실행 환경을 제공하고, 동일한 프로그램을 다양한 플랫폼에서 실행할 수 있도록 하는 것이다.

## 2. 시스템 어디에서 등장하는가

자바는 운영체제와 애플리케이션 사이에서 동작한다.

실행 구조는 다음과 같다.

```
Application
      ↓
Java Runtime
      ↓
Java Virtual Machine
      ↓
Operating System
      ↓
Hardware
```

자바는 다음 영역에서 사용된다.

- 애플리케이션 구현
- 라이브러리 실행
- 네트워크 서비스
- 배치 프로그램
- 분산 시스템
- 데스크톱 프로그램

자바 프로그램은 운영체제에서 직접 실행되지 않고 JVM을 통해 실행된다.

## 3. 어떤 자원(CPU/Memory/Network/Disk)에 가장 영향이 큰가

자바는 시스템의 모든 주요 자원을 사용한다.

| 자원 | 영향 |
|---|---|
| CPU | 바이트코드 실행, JIT 컴파일 |
| Memory | Heap, Metaspace, Stack 관리 |
| Network | 소켓 통신, 데이터 송수신 |
| Disk | 클래스 로딩, 파일 입출력 |

### CPU

자바는 프로그램 실행 과정에서 CPU를 사용한다.

**대표 작업**
- 바이트코드 실행
- JIT 컴파일
- 가비지 컬렉션
- 스레드 실행

### Memory

자바는 실행 중 메모리를 관리한다.

**대표 영역**
- Heap
- Metaspace
- Thread Stack
- Direct Memory

### Network

자바는 네트워크 자원을 사용할 수 있다.

**대표 작업**
- TCP
- UDP
- HTTP
- 데이터 송수신

### Disk

자바는 실행 과정에서 저장 장치를 사용할 수 있다.

**대표 작업**
- Class Loading
- File I/O
- Log 저장
- 데이터 저장

## 4. 왜 중요한가

자바는 운영체제와 독립적인 실행 환경을 제공한다.

또한 실행 중 다양한 기능을 런타임에서 제공한다.

**대표 기능**
- 메모리 관리
- 가비지 컬렉션
- 예외 처리
- 동시성 지원
- 동적 클래스 로딩

이러한 기능은 프로그램의 개발과 운영을 단순화하지만, 런타임 동작을 이해해야 성능과 안정성을 관리할 수 있다.

## 5. 실제 장애와 어떤 관련이 있는가

운영 환경에서 발생하는 많은 장애는 자바 런타임 동작과 연결된다.

### CPU 관련

**원인**
- JIT 컴파일
- GC 수행
- 과도한 연산

**결과**
- CPU Usage 증가
- Latency 증가

### Memory 관련

**원인**
- Heap 부족
- 메모리 누수
- Metaspace 증가
- Direct Memory 부족

**결과**
- OutOfMemoryError
- GC 증가
- 응답시간 증가

### Thread 관련

**원인**
- 과도한 스레드 생성
- 동기화 문제

**결과**
- Deadlock
- Lock Contention
- Thread Exhaustion

### Network 관련

**원인**
- 연결 관리 실패
- Timeout 설정 오류

**결과**
- Connection Exhaustion
- Retry 증가
- 응답 지연

### Disk 관련

**원인**
- 과도한 로그 기록
- 빈번한 파일 접근

**결과**
- Disk I/O 증가
- 응답 지연

## 6. 현재 문맥에서 꼭 알아야 하는 핵심 메커니즘만 설명

E2E SRE 문서를 읽는 관점에서는 자바를 다음 구조로 이해하면 충분하다.

### 컴파일

```
Source Code
      ↓
Bytecode
```

### 실행

```
Bytecode
      ↓
JVM
      ↓
Operating System
```

### 런타임 관리

JVM은 실행 중 다음 기능을 수행한다.

- 메모리 관리
- 스레드 관리
- 클래스 로딩
- 가비지 컬렉션
- 예외 처리

### 실행 최적화

프로그램 실행 중 일부 코드는 최적화되어 실행된다.

```
Bytecode
      ↓
실행
      ↓
최적화
      ↓
Native Code
```

### 핵심 흐름

```
Source Code
      ↓
Compile
      ↓
Bytecode
      ↓
JVM
      ↓
Operating System
      ↓
Hardware
```

E2E SRE 관점에서는

- 프로그램이 어떻게 작성되었는가

보다

- JVM이 프로그램을 어떻게 실행하는가

를 이해하는 것이 중요하다.

자바 자체는 운영체제가 관리하는 대상이 아니며, JVM 프로세스로 실행된다.

## E2E SRE 문서 관점 핵심 정리

자바는 운영체제 위에서 직접 실행되는 프로그램이 아니라, JVM을 통해 실행되는 객체 지향 프로그래밍 언어이자 플랫폼이다.

핵심 구조는

```
Source Code
      ↓
Compile
      ↓
Bytecode
      ↓
JVM
      ↓
Operating System
```

이다.

E2E SRE 관점에서는

```
Java
      ↓
JVM Runtime
      ↓
CPU / Memory / Thread / Network / Disk 사용 특성
      ↓
Observability
```

의 흐름으로 이해하면 된다.

운영 환경에서 관측되는

- GC 증가
- Heap 부족
- Metaspace 증가
- Thread 증가
- CPU 사용률 증가
- OutOfMemoryError

등은 대부분 JVM의 런타임 동작과 자원 관리 방식에서 비롯된다.

따라서 자바 기반 시스템을 분석할 때는 언어 자체보다 JVM의 실행 구조와 런타임 특성을 이해하는 것이 핵심이다.
