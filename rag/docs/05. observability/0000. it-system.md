# IT System (정보기술 시스템)

> 정독: 1회

## 1. 무엇인가

정보기술 시스템(IT System)은 데이터를 수집, 저장, 처리, 전송 및 관리하여 조직의 업무와 서비스를 수행하는 하드웨어, 소프트웨어, 네트워크 및 데이터가 통합된 시스템이다.

IT 시스템은 하나의 장비나 소프트웨어를 의미하는 것이 아니라, 여러 구성 요소가 함께 동작하여 하나의 서비스를 제공하는 전체 시스템을 의미한다.

주요 목적은 다음과 같다.

- 데이터 수집
- 데이터 저장
- 데이터 처리
- 데이터 전송
- 서비스 제공
- 운영 관리

IT 시스템은 사용자의 요청을 처리하고 필요한 결과를 제공하는 기반 시스템이다.

## 2. 시스템 어디에서 등장하는가

IT 시스템은 사용자와 물리적인 컴퓨팅 자원 사이에서 서비스를 제공하는 전체 환경이다.

전체 구조는 다음과 같다.

```
User
      ↓
Application
      ↓
IT System
      ↓
Hardware
```

IT 시스템은 일반적으로 다음 요소로 구성된다.

- Hardware
- Software
- Network
- Data
- Operation

전체 서비스 흐름은 다음과 같다.

```
User Request
      ↓
Network
      ↓
Application
      ↓
Data Processing
      ↓
Response
```

## 3. 어떤 자원(CPU/Memory/Network/Disk)에 가장 영향이 큰가

IT 시스템은 시스템의 모든 주요 자원을 사용한다.

| 자원 | 영향 |
|---|---|
| CPU | 데이터 처리 및 연산 |
| Memory | 프로그램 실행 및 데이터 관리 |
| Network | 시스템 간 통신 |
| Disk | 데이터 저장 및 조회 |

### CPU

대표 작업

- 프로세스 실행
- 데이터 연산
- 스케줄링

### Memory

대표 작업

- 프로그램 실행
- 캐시
- 버퍼
- 데이터 저장

### Network

대표 작업

- 데이터 전송
- 서비스 통신
- 원격 연결

### Disk

대표 작업

- 파일 저장
- 데이터 저장
- 로그 기록
- 백업

## 4. 왜 중요한가

현대의 대부분의 서비스는 IT 시스템 위에서 동작한다.

IT 시스템은 다음과 같은 품질 특성에 직접적인 영향을 준다.

- 가용성
- 신뢰성
- 확장성
- 성능
- 보안성
- 유지보수성

IT 시스템의 품질은 서비스의 안정성과 운영 효율성을 결정한다.

## 5. 실제 장애와 어떤 관련이 있는가

운영 환경에서는 IT 시스템의 다양한 구성 요소에서 장애가 발생할 수 있다.

### CPU 관련

**원인**

- CPU 과부하
- 프로세스 증가
- 연산량 증가

**결과**

- CPU Usage 증가
- Latency 증가
- 처리량 감소

### Memory 관련

**원인**

- Memory 부족
- 메모리 누수
- 캐시 증가

**결과**

- Memory Usage 증가
- OOM
- 응답시간 증가

### Network 관련

**원인**

- Network 지연
- 패킷 손실
- 대역폭 부족

**결과**

- Timeout
- Connection Failure
- 서비스 지연

### Disk 관련

**원인**

- Disk I/O 증가
- 저장 공간 부족
- 디스크 장애

**결과**

- Storage Failure
- 응답시간 증가
- 서비스 중단

### 시스템 관련

**원인**

- 소프트웨어 오류
- 설정 오류
- 하드웨어 장애
- 운영 오류

**결과**

- 서비스 장애
- 데이터 손실
- 복구 지연

## 6. 현재 문맥에서 꼭 알아야 하는 핵심 메커니즘만 설명

E2E SRE 문서를 읽는 관점에서는 IT 시스템을 다음 여섯 가지 구성 요소로 이해하면 충분하다.

### Hardware

연산과 저장을 수행하는 물리적 자원이다.

- CPU
- Memory
- Disk
- Network Device

### Software

서비스를 수행하는 프로그램이다.

- Operating System
- Application
- Middleware

### Network

시스템 간 데이터를 전달한다.

- Routing
- Switching
- Communication

### Data

서비스 수행에 필요한 정보를 저장하고 관리한다.

- Create
- Read
- Update
- Delete

### Process

업무를 처리하는 절차와 실행 흐름이다.

- Input
- Processing
- Output

### Operation

시스템을 지속적으로 운영하고 관리한다.

- Deployment
- Monitoring
- Backup
- Recovery

### 핵심 흐름

```
User
      ↓
Application
      ↓
IT System
      ↓
Data Processing
      ↓
Service
```

E2E SRE 관점에서는

> 어떤 장비를 사용하는가

보다

- 서비스가 어떻게 실행되는가
- 데이터가 어떻게 처리되는가
- 자원이 어떻게 사용되는가
- 장애가 발생하면 어떻게 복구되는가

를 이해하는 것이 중요하다.

## 7. Linux / Runtime / Kubernetes에서 어디서 관측되는가

- Network Usage

## E2E SRE 문서 관점 핵심 정리

IT 시스템은

> 데이터를 수집하고, 저장하고, 처리하고, 전송하여 서비스를 제공하는 통합 시스템이다.

핵심 구성 요소는

- Hardware
- Software
- Network
- Data
- Process
- Operation

이다.

E2E SRE 관점에서는

```
User
      ↓
Application
      ↓
IT System
      ↓
CPU / Memory / Network / Disk 사용 특성
      ↓
Observability
```

의 흐름으로 이해하면 된다.

운영 환경에서 관측되는

- CPU Usage 증가
- Memory 부족
- Network Timeout
- Disk I/O 증가
- Application Error
- Node 장애
- 서비스 중단

등은 대부분 IT 시스템을 구성하는 하드웨어, 소프트웨어, 네트워크 및 데이터 처리 과정에서 발생한다.

IT 시스템의 핵심은 개별 기술이 아니라, 여러 구성 요소가 함께 동작하여 데이터를 처리하고 서비스를 안정적으로 제공하는 전체 운영 환경을 의미한다.
