# 컴파일레이션 프로세스 (Compilation Process)

> 정독: 0회

## 1. 이 기술이 무엇인가

컴파일레이션 프로세스(Compilation Process)는:

> 사람이 작성한 소스 프로그램을 타깃 플랫폼에서 실행 가능한 기계어 형태로 변환하는 전체 과정

핵심은 단순한 언어 번역이 아닙니다. 컴파일러는 다음을 수행합니다.

- 문법 분석
- 의미 분석
- 최적화
- 기계어 생성
- 데이터 배치 결정
- 정렬 적용
- 패딩 적용
- 실행 파일 생성

```
논리적 프로그램
↓
물리적 실행 코드
```

로 변환하는 전체 공정입니다.

---

## 2. 시스템 어디에서 등장하는가

컴파일레이션은 실행 이전 단계에서 발생합니다.

```
소스 프로그램
↓
컴파일레이션
↓
오브젝트 파일
↓
링킹
↓
실행 파일
↓
로더
↓
프로세스 생성
↓
CPU 실행
```

등장 위치: 개발 환경, 빌드 서버, CI/CD 시스템, 컴파일러 툴체인

---

## 3. 어떤 자원에 가장 영향이 큰가

컴파일 시점에는 **CPU**와 **Memory** 영향이 가장 큽니다.

| 자원 | 역할 |
|------|------|
| CPU | 구문 분석, 최적화, 기계어 생성 수행 |
| Memory | AST, 중간 표현(IR), 심볼 테이블, 최적화 데이터 보관 |
| Disk | 오브젝트 파일, 라이브러리, 실행 파일, 디버그 심볼 생성 |
| Network | 영향 일반적으로 작음 |

---

## 4. 왜 중요한가

실행되는 프로그램의 실제 형태가 여기서 결정됩니다. 컴파일 과정에서 다음이 확정됩니다.

- 어떤 기계어를 생성할 것인가
- 어떤 레지스터를 사용할 것인가
- 어떤 메모리 레이아웃을 사용할 것인가

비트 필드 문맥에서는 특히 중요합니다. 비트 폭, 부호 속성, 정렬, 패딩, 레이아웃이 모두 컴파일 과정에서 결정되기 때문입니다.

---

## 5. 실제 장애와 어떤 관련이 있는가

### ABI 불일치

서로 다른 컴파일 옵션으로 인해 호출 규약 차이, 정렬 차이, 구조체 크기 차이가 발생할 수 있습니다.

### 플랫폼 이식 실패

x86에서는 정상이지만 ARM에서는 오류가 발생하는 경우가 있습니다.

### 구조체 레이아웃 문제

비트 필드가 포함된 경우 예상 크기와 실제 크기가 다르거나, 패딩 위치가 달라질 수 있습니다.

### 최적화 관련 문제

고급 최적화 과정에서 타이밍 변화, 경쟁 조건 노출, 정의되지 않은 동작 노출이 발생할 수 있습니다.

## 6. 핵심 메커니즘

현재까지 등장한 개념을 연결하면 컴파일레이션은 다음 6단계 역할을 수행합니다.

### ① 논리 구조 해석

소스 코드를 이해합니다.

```c
struct Config {
    unsigned int mode : 3;
};
```

### ② 비트 필드 정보 수집

멤버 이름, 비트 폭, 부호 속성, 선언 순서를 수집합니다.

### ③ 타깃 플랫폼 정보 로드

CPU 아키텍처, 엔디언, ABI, 정렬 규칙을 확인합니다.

### ④ 레이아웃 생성

비트 위치, 비트 오프셋, 패딩 위치, 정렬 단위를 결정합니다.

### ⑤ 기계어 생성

`Shift`, `Mask`, `Load`, `Store` 연산을 생성합니다.

### ⑥ 최종 바이너리 생성

실행 파일, 라이브러리, 오브젝트 파일을 생성합니다.

> **핵심 사실:** 비트 필드의 물리적 형태는 소스 코드가 아니라 **컴파일레이션 과정에서 확정**된다.

## 7. Linux / Runtime / K8s에서 어디서 관측되는가

### Linux

```bash
# 컴파일
gcc main.c
clang main.c

# 전처리 결과 확인
gcc -E main.c

# 어셈블리 생성
gcc -S main.c

# 오브젝트 파일 생성
gcc -c main.c

# 실행 파일 분석
file app
readelf app
objdump -d app
```

### Runtime

런타임은 컴파일 결과물을 사용합니다.

관측 가능 대상: 메모리 레이아웃, 레지스터 사용, 기계어, 프로세스 주소 공간

### Kubernetes

컴파일은 일반적으로 개발 PC, 빌드 서버, CI 파이프라인에서 수행됩니다.

Kubernetes에는 컴파일 결과물(컨테이너 이미지, 실행 파일)만 배포됩니다.
