# 소스 프로그램 (Source Program)

> 정독: 0회

## 1. 이 기술이 무엇인가

소스 프로그램(Source Program)은:

> 개발자가 프로그래밍 언어 문법을 사용하여 작성한 원본 프로그램

소스 프로그램은 사람이 이해할 수 있는 형태의 논리 명세이며, CPU가 직접 실행할 수 있는 형태는 아닙니다.

포함되는 요소:

- 변수 선언
- 자료구조 정의
- 함수 정의
- 조건문
- 반복문
- 알고리즘

**핵심:**

소스 프로그램은 **"무엇을 할 것인가"** 를 기술하는 단계이며,  

**"어떻게 실행될 것인가"** 는 아직 결정되지 않은 상태입니다.

---

## 2. 시스템 어디에서 등장하는가

소스 프로그램은 소프트웨어 개발의 출발점입니다.

```
개발자
↓
소스 프로그램
↓
컴파일러 / 인터프리터
↓
실행 코드
↓
CPU 실행
```

대표적인 분야:

- 운영체제
- 드라이버
- 데이터베이스
- 웹 서버
- 네트워크 장비
- 임베디드 시스템
- 게임 엔진
- AI 시스템

모두 소스 프로그램에서 시작됩니다.

---

## 3. 어떤 자원에 가장 영향이 큰가

소스 프로그램 자체는 실행되지 않으므로 직접 자원을 사용하지 않습니다. 그러나 최종적으로는 **CPU**와 **Memory**에 가장 큰 영향을 미칩니다.

소스 프로그램이 결정하는 것:

- 어떤 연산을 수행할 것인가
- 어떤 자료구조를 사용할 것인가
- 메모리를 어떻게 사용할 것인가

간접적으로는 **Network**와 **Disk**의 사용 패턴도 결정합니다.

---

## 4. 왜 중요한가

모든 실행 코드의 원형이기 때문입니다. 컴파일러는 소스 프로그램에 없는 기능을 만들어내지 않습니다.

소스 프로그램으로부터 생성되는 것:

- 실행 파일
- 라이브러리
- 커널
- 컨테이너 이미지

소스 프로그램 품질에 의해 결정되는 것:

- 가독성
- 유지보수성
- 확장성
- 안전성

---

## 5. 실제 장애와 어떤 관련이 있는가

실제 운영 장애의 상당수는 소스 프로그램 단계에서 시작됩니다.

| 분류 | 예시 |
|------|------|
| 논리 오류 | 조건문 오류, 상태 전이 오류, 예외 처리 누락 |
| 메모리 오류 | 잘못된 포인터, 버퍼 오버런, 메모리 누수 |
| 동시성 오류 | 경쟁 조건, 데드락, 순서 역전 |
| 성능 문제 | 비효율적 알고리즘, 과도한 복사, 불필요한 I/O |

> 운영 환경에서 보이는 장애는 대부분 **실행 중 발견**되지만,  
> 원인은 **소스 프로그램**에 존재하는 경우가 많습니다.

---

## 6. 핵심 메커니즘

현재 문맥에서 가장 중요한 것은 다음입니다.

```
소스 프로그램 ≠ 실제 메모리 구조
```

예를 들어 아래 선언은 아직 단순한 명세일 뿐입니다.

```c
struct Config {
    unsigned int mode : 3;
};
```

실제 메모리 구조가 되기까지의 과정:

```
소스 프로그램
↓
구문 분석 (AST)
↓
타입 분석
↓
레이아웃 결정
↓
정렬 결정
↓
패딩 결정
↓
기계어 생성
↓
실제 메모리 배치
```

따라서:

- **소스 프로그램** → 논리적 정의
- **실행 코드** → 물리적 실체

비트 필드 문맥에서 보면:

| 단계 | 결정 주체 |
|------|-----------|
| 비트 폭, 부호 속성, 비트 필드 선언 | 소스 프로그램 |
| 실제 비트 위치, 패딩, 정렬, 비트 패턴 | 컴파일 이후 |

## 7. Linux / Runtime / K8s에서 어디서 관측되는가

### Linux

소스 파일 형태로 존재합니다.

```
*.c  *.cpp  *.h  *.hpp  *.rs  *.go
```

```bash
# 컴파일
gcc main.c
clang main.c

# 전처리 결과 확인
gcc -E main.c

# 어셈블리 생성
gcc -S main.c
```

### Runtime

런타임에서는 소스 프로그램이 직접 존재하지 않습니다. 실행 중인 것은 **컴파일 결과물**입니다.

### Kubernetes

컨테이너 내부에는 일반적으로 실행 파일, 라이브러리, 설정 파일만 존재합니다.

소스 프로그램은 보통 아래에서 관리됩니다.

- Git Repository
- CI Pipeline
- Build Server
